# Размещение «Полки» в Timeweb Apps

Домен пользователя: **polka.net.ru**, проект в Timeweb: **Полка**. Домен куплен пользователем; привязка к приложению и выпуск HTTPS ещё не проверены. Подготовка этих файлов ничего не публикует.

## Что запускает контейнер

Один Node.js 22 процесс отдаёт `apps/web/dist` и маршруты `/api/...` на одном домене. Dockerfile собирает фронтенд и бэкенд в отдельных от итогового образа стадиях. Секреты, Git, локальные node_modules и сборки исключены через `.dockerignore`. Итоговый контейнер работает от пользователя `node`, слушает `0.0.0.0:8080`, проверка здоровья — `GET /api/health`.

В Docker-сборке фронтенда `VITE_AI_API_URL=/api/ai/recipes` — публичный относительный маршрут, не ключ. Ключи передаются только серверу при запуске. Обычная сборка для GitHub Pages сохраняет прежний режим и может использовать отдельный API.

Контейнер включает Telegram-вход и серверное пользовательское хранилище PostgreSQL. Настоящий аккаунт требует `BOT_TOKEN`, `DATABASE_URL` и применения миграций `001` и `002`; демо доступно отдельно и не загружается в аккаунт автоматически. Это не завершение всех этапов ROADMAP: голос и Timeweb AI Gateway не реализованы. Текущий провайдер ИИ — Z.ai. Отдельный бот пока остаётся сервисом Cloudflare Workers; перенос его обработчика в этот контейнер не выполнен.

Проверено 17 ноября 2026: образ собран локально; HTTP-проверки HTML/JS/CSS/фотографий, каталогов, HEAD, CORS и запрета неавторизованных ИИ-запросов прошли. После подключения пользовательского хранилища `npm run check`: 153 теста прошли, 10 интеграционных PostgreSQL пропущены в обычном запуске без тестовой БД; типизация и обе сборки прошли. Отдельно все 10 интеграционных проверок выполнены на изолированной PostgreSQL. Сквозная HTTP-проверка проверила подписанный тестовый вход, сессию без cookies, историю больше 24 КБ, повтор запроса, разделение двух аккаунтов и сохранность после повторного входа. Облачный деплой и настоящий Telegram-клиент этим не подтверждаются; визуальную проверку браузера инструмент выполнить не смог.

`npm audit` сообщил о 6 уязвимых пакетах в инструментах разработки (цепочки Vitest/Tinypool/Mocker и Wrangler/Miniflare/Undici). Эти инструменты не входят в итоговый образ; при установке серверных runtime-зависимостей npm сообщил 0 уязвимостей. Обновление тестового инструментария и Cloudflare SDK остаётся отдельной задачей; `npm audit fix --force` автоматически не выполнялся. Это не является полным сканированием ОС базового образа.

## Проверка локально

Нужны Docker Desktop/Engine и доступ к реестру образов и npm:

```sh
docker build -t polka-app:local .
docker run --rm --name polka-app-local -p 127.0.0.1:8080:8080 polka-app:local
```

Открыть `http://localhost:8080`, API — `http://localhost:8080/api/health`. Без окружения доступен экран входа и явно выбираемое демо; каталоги публичные, запросы к ИИ не выполняются, аккаунты сообщают об отсутствии БД.

Для локальной проверки с `.env` добавь к `docker run` опцию `--env-file .env`; значения файла не копируются в образ. `ALLOWED_ORIGIN` должен содержать точный адрес браузера, например `http://localhost:8080`. Если БД запущена на Mac, адрес `127.0.0.1` внутри контейнера означает сам контейнер: используй отдельную локальную конфигурацию с `host.docker.internal`. Не заменяй рабочие настройки базы наугад. Локальный обход Telegram-авторизации не работает при публичной привязке `0.0.0.0`, даже если установлен `BACKEND_LOCAL_DEV=1`.

## Настройки Timeweb

После загрузки проверенных изменений в GitHub пользователем:

1. Apps → создать приложение из репозитория `eshevlyakova/polka`, ветка `main`.
2. Фреймворк **Dockerfile**, контекст — корень репозитория, файл — `Dockerfile`. Не выбирать отдельный React-хостинг.
3. Название `polka-app`, проект «Полка», регион Москва. Начальный ориентир — один экземпляр 2 vCPU / 2 ГБ RAM; доступные тарифы и итоговую стоимость проверить в панели. При нехватке памяти сборки потребуется увеличить ресурсы.
4. Переменные окружения ниже. Порт уже указан в Dockerfile через `EXPOSE 8080`; HTTPS на внешнем адресе обслуживает платформа. Внешний таймаут запросов ИИ должен быть не меньше 90 секунд.
5. После деплоя проверить технический домен и `/api/health`. Для проверки POST с технического домена его точный origin нужно явно добавить в `ALLOWED_ORIGIN`.
6. В настройках доменов приложения привязать **polka.net.ru**. Проверить DNS и статус бесплатного Let's Encrypt. Адреса DNS брать только из панели этого приложения.
7. Проверить `https://polka.net.ru` и `https://polka.net.ru/api/health`.

### Окружение сервера

| Имя              | Значение                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `APP_ORIGIN`     | `https://polka.net.ru`                                                                                                    |
| `ALLOWED_ORIGIN` | `https://polka.net.ru`; дополнительные точные origin через запятую, без путей и завершающего `/`                          |
| `API_GLM`        | Текущий ключ Z.ai, только в секретах/переменных сервера                                                                   |
| `BOT_TOKEN`      | Настоящий токен существующего Telegram-бота, только на сервере                                                            |
| `DATABASE_URL`   | Строка подключения из настроек PostgreSQL с требуемыми провайдером параметрами TLS; не локальная строка из `.env.example` |

`NODE_ENV=production`, `HOST=0.0.0.0`, `PORT=8080` и `WEB_DIST=/app/apps/web/dist` уже заданы в Dockerfile. `BACKEND_LOCAL_DEV` в облаке не устанавливать. `AI_TEST_CODE` не обязателен: предпочтителен проверенный вход из Telegram. Никогда не добавлять секреты в `VITE_*`, Dockerfile, Git или чат.

### PostgreSQL и миграции

База создаётся отдельно от приложения. Миграции не запускаются автоматически при рестарте и не удаляют существующие данные. В окружении с нужным `DATABASE_URL`, из корня готового контейнера:

```sh
node apps/backend/dist/apps/backend/src/db/migrate.js
```

Перед первым запуском проверить, что строка подключения указывает на нужную базу, и настроить резервное копирование. Если в панели нет консоли контейнера, выполнить `npm run db:migrate` локально с отдельной безопасной конфигурацией доступа к этой БД. Не открывать публичный HTTP-маршрут миграций.

Подключение Mini App к рабочему боту, смена webhook, публикация и push выполняются только отдельным согласованным шагом.

## Выбор ИИ: пока кандидаты

- Текст: **DeepSeek V4.1 Flash** через AI Gateway — проверить понимание пожеланий, исключений и адаптацию известных рецептов на одинаковом наборе запросов.
- Изображения: **Gemini 3.8 Flash** — проверить реальный model ID, поддержку изображений, чтение чеков и таблиц КБЖУ через Timeweb. Наличие названия в каталоге не заменяет проверку API.
- Голос: целевой кандидат **GPT-Transcribe**, если Timeweb предоставит его в Audio API. Timeweb пока документирует `gpt-4o-mini-transcribe`/`gpt-4o-transcribe`; OpenAI объявил их устаревающими, поэтому не фиксировать новую интеграцию без проверки доступных замен. Озвучивание ответов не нужно.

Ни одна из этих моделей ещё не подключена. Цены конкретных моделей нужно брать из их карточек в AI Gateway, отдельно для входа/выхода/аудио/изображений; цены прямого API производителя нельзя считать ценами Timeweb. Месячный расход рассчитывается по числу сценариев, длине контекста, изображениям, длительности аудио и повторам. Пока реальные запросы не замерены, фиксированная сумма в месяц была бы предположением.
