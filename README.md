# Полка — Telegram Mini App MVP

React + TypeScript + Vite; Telegram bot on Cloudflare Workers. A working local-first prototype, not a production nutrition database. No bot token is included. Use a NEW token after revoking the one previously shared in chat.

## Что работает

- Онбординг, цель калорий, исключения по названиям, фильтр времени.
- Полка: количество в граммах, дата, редактирование и удаление.
- Небольшая база и создание своих продуктов/готовых блюд по значениям на 100 г.
- Дневник любой еды: количество, дата, приём пищи, обозначение приблизительной записи, удаление и переименование.
- Четыре рецепта, изменение состава, добавление ингредиентов; своё домашнее блюдо.
- Приготовление списывает запасы по ближайшему сроку. Еда списывает долю готового блюда, НЕ ингредиенты второй раз. Удаление записи возвращает долю блюда.
- Готовые остатки, простые достижения, экспорт и восстановление JSON.
- Бот: /start, /help, /stop, кнопка Mini App, webhook с секретом.
- Напоминания о ближайших сроках: по явной кнопке отправляются только названия/сроки; расписание на сервере. Дневник на сервер не передаётся.

## Что ещё не реализовано

ИИ и чеки, полноценная пищевая база/меню кафе, масса готового блюда, отдельные цели БЖУ, напоминания о разморозке и времени готовки, синхронизация дневника, автоматическое обновление сроков на сервере, каталог личных рецептов. Своё блюдо сохраняется как приготовленная партия; шаблон пока не сохраняется. Формы порции и редактирования оформлены внутри приложения; системные prompt-диалоги не используются. У записи можно изменить название, дату и приём пищи; для изменения количеств удалите запись и добавьте заново. Логотип в интерфейсе — CSS/текстовая адаптация, не точный векторный оригинал. Маскот и иллюстрации еды — отдельные SVG-компоненты (PearMascot, FoodArt).

## Локальный запуск

Node.js 22.12+ (лучше актуальная LTS), npm.

```bash
npm ci
npm run dev
```

Открой адрес, выведенный Vite. При первом открытии автоматически создаётся вымышленный аккаунт: 11 продуктов со сроками, история КБЖУ за 14 дней и готовое блюдо. Даты относительны дню первого запуска. Вводите и меняйте данные как обычно; при перезагрузке они не подменяются. Для старого пустого аккаунта откройте Настройки → «Загрузить демоаккаунт заново» (текущие данные будут заменены только после подтверждения). Бэкенд не обязателен для полки, рецептов и дневника. Интернет нужен для загрузки Telegram SDK/шрифта; при отсутствии шрифта используется системный.

```bash
npm run check
```

Это TypeScript-проверка обоих приложений, тесты домена/авторизации и production build.

## Архитектура

- `apps/web/src/domain`: сущности, чистые расчёты и операции cook/eat/deleteEntry. Не зависят от React.
- `apps/web/src/data`: маленький исходный каталог и рецепты, приблизительные значения.
- `apps/web/src/storage`: интерфейс StateRepository, LocalRepository и проверка импортированных данных.
- `apps/web/src/hooks`: загрузка и сохранение состояния, защита повреждённых сохранений.
- `apps/web/src/components`: общие UI-компоненты; `components/dialogs` — отдельные формы.
- `apps/web/src/screens`: Сегодня, Полка, Рецепты, Дневник.
- `apps/web/src/App.tsx`: каркас и навигация. `hooks/useAppController.tsx` связывает состояние с экранами; `usePolkaState` отвечает за сохранение.
- `apps/web/src/telegram.ts`: адаптер Telegram. initDataUnsafe используется только для разделения локальных ключей; сервер ему не доверяет.
- `apps/bot/src/auth.ts`: HMAC-проверка initData и срока авторизации.
- `apps/bot/src/telegram.ts`: Telegram API, ключ только на сервере.
- `apps/bot/src/index.ts`: маршрутизация. `webhook.ts`, `reminders.ts`, `scheduler.ts` — отдельные обработчики.
- `apps/bot/migrations`: D1 хранит получателей и напоминания, не дневник.
- `tests`: регрессии расчётов, остатков и подписи Telegram.

Ключ localStorage включает id пользователя Telegram; браузер вне Telegram имеет отдельное сохранение. Структура содержит version для будущих миграций. Для серверной базы нужно будет сделать асинхронный repository и обработку конфликтов, а не просто заменить URL. Данные не шифруются и не синхронизируются; экспортируйте резервную копию. Ошибка чтения не перезаписывает старое сохранение.

## Фронт на GitHub Pages

1. Создай репозиторий и загрузи СОДЕРЖИМОЕ папки проекта в его корень (package.json должен быть в корне).
2. Settings → Pages → Source: GitHub Actions.
3. Workflow `.github/workflows/pages.yml` соберёт и опубликует `apps/web/dist`.
4. Получи HTTPS URL вида `https://USER.github.io/REPO/`.
5. В BotFather выбери /mybots → бот → Bot Settings → Menu Button и укажи этот URL. Интерфейс уже можно открыть, собственного сервера для этого не требуется.

Vite base './' поддерживает путь репозитория. Для кнопки /start нужен Worker ниже. Домен покупать не нужно.

## Бот на Cloudflare Workers

Бэкенд написан под Workers Web APIs, не под постоянно работающий Node.js процесс. D1 нужен только для расписания/получателей и дедупликации webhook. Аккаунт Cloudflare и доступные лимиты проверяйте при регистрации.

```bash
cd apps/bot
npx wrangler login
npx wrangler d1 create polka-reminders
```

Скопируй выданный database_id в `wrangler.jsonc`. Замени WEB_APP_URL на адрес Pages и ALLOWED_ORIGIN на origin без пути, например `https://USER.github.io`. HTTPS обязателен.

```bash
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npm run migrate:remote
npm run deploy
```

WEBHOOK_SECRET — случайная строка, например сгенерированная `openssl rand -hex 32`. Сохрани её, она понадобится при установке webhook. Никогда не помещай BOT_TOKEN в VITE_* переменные: они публичны.

Для локальной разработки бота скопируй `.dev.vars.example` в `.dev.vars`, заполни значения и выполни `npm run migrate:local`, затем `npm run dev`. Telegram не доставляет webhook на localhost без HTTPS-туннеля; автоматические тесты не отправляют сообщения.

## Подключить фронт к Worker

В GitHub Settings → Secrets and variables → Actions → Variables добавь `VITE_API_URL` с адресом Worker, например `https://polka-bot.ACCOUNT.workers.dev` (без завершающего слеша). Перезапусти workflow. Для локального фронта значение можно записать в `apps/web/.env.local`; в Worker разреши локальный origin только для разработки.

Настрой webhook и меню скриптом из корня проекта. Он читает секреты только из окружения:

```bash
node --env-file=.env scripts/setup-bot.mjs
```

В локальном `.env` должны быть BOT_TOKEN, WEBHOOK_SECRET, WORKER_URL и WEB_APP_URL. Файл игнорируется git. Скрипт меняет настройки существующего бота; запускайте только для своего бота.

После этого /start → «Открыть Полку». Для напоминаний сначала /start, затем добавь срок и нажми «Обновить напоминания» на полке.

## Напоминания: точные ограничения

- Только продукты со сроком сегодня, завтра или послезавтра.
- Задача планируется на 09:00 Москвы за день до срока; если время прошло — на ближайший cron, который запускается каждые 15 минут.
- После изменения или удаления продукта нажми «Обновить напоминания» снова. Иначе сервер не узнает о локальных изменениях.
- /stop удаляет ожидающие задачи; уже отправленные сообщения не отзываются.
- При сбое Telegram повтор через час. Редкий дубль возможен, если Telegram принял сообщение, а сервер не успел зафиксировать отправку. Exactly-once не обещается.
- Новая синхронизация заменяет прежние задачи; повторная синхронизация после отправки может повторить напоминание. Для production нужны устойчивые id партии и дедупликация отправленных событий.
- initData действует один час на сервере: при ошибке открой Mini App заново.

## Расчёты и границы

КБЖУ = сумма значений на 100 г × фактическая масса / 100. Порция — доля всего блюда, предполагающая равномерный состав. Учитывайте сырой/готовый продукт, масло и соусы. Граммы приготовленного блюда пока не поддерживаются. Прототип не оценивает безопасность еды; указанный срок — напоминание, а не гарантия свежести. Каталог не является сертифицированной базой.

## Проверка этой сборки

TypeScript, production build и автоматические тесты домена, авторизации и React проходят. Тест React проверяет ввод, сохранение и восстановление после повторного открытия. Реальный Telegram и облачный деплой требуют ваших аккаунтов и нового токена; они не выполнялись. Мобильные экраны проверяются отдельно в headless Chromium.

## Обновление оформления и демоаккаунт

Демоаккаунт создаётся и сохраняется один раз при отсутствии данных. Существующие записи никогда не заменяются автоматически. Старый пустой аккаунт можно явно заменить демоданными в настройках. Каталог и генератор демонстрационных записей разделены (`data/catalog.ts`, `data/demo.ts`). Маскот и миниатюры продуктов — локальные SVG; фотографии рецептов хранятся в сборке. Цвета/карточки/типографика приближены к согласованной концепции; для рецептов используются реальные фотографии Pexels и Wikimedia Commons; авторы и лицензии доступны в приложении.

## UX-обновление

Единая шкала отступов, основной текст/поля 16 px, подписи 13–15 px, зоны нажатия от 44 px. Меню разделов в шапке, история переходов и кнопки назад в экранах/формах; Telegram BackButton. Диалоги закрываются Escape, удерживают фокус и блокируют прокрутку фона. Редактирование запасов и запись порций — отдельные формы с выбором единиц, даты и приёма пищи.

## Визуальная редакция и моки

Реплика груши восстановлена. Главная показывает реальные итоги из локальных записей и краткую ленту приёмов пищи. Дневник сгруппирован по приёмам, есть недельная лента и заметки. Демоистория за 14 дней разнообразна; фото не используются для расчёта КБЖУ. Источники/лицензии: `apps/web/src/data/photoCredits.ts` и `PHOTO_CREDITS.md`. Сгенерированные фото не входят в проект.

## Загрузка моков и страница настроек

Новая установка и старое полностью пустое сохранение автоматически получают демоаккаунт. Это разовая миграция: дальнейшее удаление данных не приводит к постоянному повторному заполнению. Аккаунты с пользовательскими записями/продуктами не заменяются. Для полностью демонстрационного аккаунта при открытии в другой день сдвигаются только даты, чтобы сегодняшний счётчик не выглядел пустым; изменения количеств и удаления сохраняются. Настройки — отдельный экран, открываемый из меню, с возвратом на предыдущий экран. Для применения обновления замените исходники и заново соберите/опубликуйте фронт; старый опубликованный билд сам не обновляется от скачивания ZIP.

## Навигация и выбор значений

У страниц меню (Сегодня, Полка, Рецепты, Дневник, Настройки) нет отдельной кнопки «Назад». Переходы доступны через меню и нижнюю навигацию. В формах и рецептах возврат сохранён; Telegram BackButton отображается во внутренних сценариях. Настройки остаются отдельной страницей в меню.

Выбор продуктов, ингредиентов, времени, приёма пищи и единиц порции использует общий компонент `Select`: оформление приложения, клавиши стрелок/Home/End, подтверждение Enter и закрытие Escape или нажатием снаружи. Значения передаются в формы через скрытые поля.

Настройки доступны пятой вкладкой нижней навигации. Кнопка меню в шапке и всплывающее меню удалены.

## Единый профиль

Пятая вкладка — «Мой профиль»: статистика, коллекция из шести достижений с локальными SVG-персонажами, цель калорий и исключения для рецептов расположены на одной странице. Отдельного экрана настроек нет. Из дневника можно перейти к этой же вкладке. Достижения рассчитываются по сохранённым данным, включая демоисторию, без отдельного журнала наград.

## Профиль и история веса

Демоаккаунт содержит вымышленный профиль Анны (23 года, 168 см), текущий вес 65,4 кг, желаемый 62 кг и восемь измерений за месяц. Старому полностью демонстрационному аккаунту без профиля данные добавляются один раз; существующий профиль не заменяется. При обновлении дат демоистории сдвигаются и даты демонстрационных измерений.

На экране «Сегодня» карточка «Моя цель» показывает текущий и желаемый вес, график измерений за последние 30 дней и изменение за показанный период. График строится по фактическим датам измерений, без прогнозов и автоматического расчёта калорий. Запись за ту же дату заменяет предыдущую. Измерение за прошлый день не меняет текущий вес, если есть более позднее. Редактирование веса в профиле создаёт измерение за сегодня; редактирование имени или цели сохраняет историю. Изменение профиля/веса снимает признак демонстрационного профиля; его даты больше не сдвигаются автоматически. Данные сохраняются локально.
