# Полка: план первой рабочей версии

Дата обсуждения: 17 ноября 2026. Основные продуктовые решения согласованы 17 ноября 2026; отметки этапов отражают их фактическую готовность. Деплой, покупки и изменения внешних сервисов этим документом не разрешаются.

## Исходное состояние до первого этапа

- React/TypeScript/Vite; `apps/web`, `apps/backend`, `apps/bot`, `shared`.
- Полка, приготовленные блюда и дневник хранятся в localStorage.
- Есть расчёты КБЖУ, раздельные приготовление/приём пищи, порции и остатки.
- Есть ИИ-разбор пожеланий, поиск в каталоге, адаптация рецептов и проверка фото чека с подтверждением.
- JSON-каталог: 501 русский рецепт; пищевая ценность: 302 брендовых записи OFF и 50 типовых продуктов. Полнота и качество каталога пока ограничены.
- Текущий провайдер — Z.ai; основные модели `glm-4.7-flash`, `glm-4.6v-flash`, резерв разбора `glm-4.5-flash`. Подключения DeepSeek/Timeweb пока нет.
- Проверка Telegram initData есть. Серверного аккаунта, сессий, пользовательской БД, голосового ввода и персональной истории предпочтений нет.
- Бот рассчитан на Cloudflare Workers/D1; в wrangler-конфигурации остаются шаблонные облачные значения. Факт рабочего внешнего подключения не подтверждён.

## Предлагаемые решения

- Вход только через Telegram: проверенный Telegram ID, создание пользователя при первом открытии, затем серверная сессия. Пароли и отдельная регистрация по почте не нужны.
- Хранить настоящие данные в PostgreSQL. localStorage использовать для кеша/черновиков, деморежим отделить. Старые данные не переносить автоматически без просмотра и подтверждения владельцем.
- Сохранить существующий стек и папки. Один прикладной backend с модулями, отдельный обработчик бота/фоновых задач; без набора микросервисов, Kubernetes и обязательного Redis на старте.
- Timeweb: фронтенд, API/обработчик бота, PostgreSQL, при необходимости временное объектное хранилище. Способ размещения выбрать по удобству сопровождения и требованиям приложения; пользователь не задаёт бюджетный лимит.
- ИИ через AI Gateway: приложение управляет данными, пользовательскими черновиками, историей и разрешениями. Модель получает только нужный контекст.
- Базу рецептов оставить; основной режим — подбор и адаптация. Генерация новых рецептов вне базы запрещена; разрешены только подбор и адаптация известных рецептов.
- КБЖУ, списание продуктов и остатки рассчитывает код. Неизвестные нутриенты и граммовки не выдумываются моделью.
- Готовая еда и еда вне рецептов доступны для дневника. Повторная запись порции не списывает сырые продукты.
- Точные сроки годности не возвращаем: внутренний приоритет скоропортящихся продуктов по дате добавления не означает определение свежести или безопасности.

Напоминания и тестирование на людях сейчас вне объёма. ИИ выбираем по качеству и разумной стоимости, без лимита бюджета от пользователя. Только адаптация рецептов из базы.
- [ ] **P1. Серверное хранение и окружения.** Модель данных, PostgreSQL, миграции, конфигурация окружения, журнал ошибок, резервные копии и проверка восстановления. Сначала подготовить локальное окружение; облачные покупки и публикацию выполнять отдельным шагом. Начато: миграции пользователей/сессий, драйвер PostgreSQL и локальный compose. Добавлено серверное хранение всего пользовательского состояния и неподтверждённые черновики по аккаунтам. Облачные резервные копии и восстановление ещё не настроены.
- [ ] **P2. Вход через Telegram.** Проверка initData и давности, создание аккаунта, сессии, доступ только к собственным данным, повторный вход. Разделение деморежима и настоящих аккаунтов; подтверждаемый перенос прежних локальных записей. Начато: серверные API входа, своего профиля и выхода; интерфейс подключён; демо отделено, перенос подтверждается пользователем. Осталось подключить рабочий домен к боту и проверить реальные Telegram-клиенты после деплоя.

Транзакции, защита от двойного нажатия/повторной доставки запроса, конфликты двух устройств и явные ошибки сохранения. Проверить бытовые меры, упаковки и приблизительный/измеренный вес блюда.
- [ ] **P4. Каталоги и слой ИИ.** Загрузить текущие продукты/рецепты в БД, проверить нутриенты и привязки ингредиентов, сохранить источники/лицензии. Поиск, штрихкоды, единицы, пользовательские продукты и модерация общих записей. Адаптер Timeweb, отдельные модели для текста/изображений/аудио, строгие ответы, ограничения расходов, отмена и безопасный резерв.
- [ ] **P5. Первое заполнение полки.** Короткое знакомство с предпочтениями; выбор «продиктовать / сфотографировать чек / вручную». Общий черновик списка, уточнение только отсутствующих важных данных, редактирование и единое подтверждение. Можно пропустить и вернуться. Ошибки, отказ в доступе к микрофону и перезагрузка не должны терять черновик.

Дизлайк рецепта не запрещает автоматически все его ингредиенты. Пользователь может сбросить историю; контекст строго разделён по аккаунтам.

Добавить метрики первого заполнения, выбора рецепта, ошибок и фактических затрат. Настроить домен/HTTPS, отдельные окружения, удаление данных и условия обработки загружаемых файлов. Проверки выполняет разработчик; тестирование на людях сейчас не планируем. Подключение рабочего бота — после подготовки приложения.

## Сценарий первого заполнения

1. Пользователь открывает Mini App из бота; вход подтверждается сервером.
2. Необязательные короткие вопросы: исключения/аллергии, что любит, обычное время готовки. Можно заполнить позже.
3. Предложение добавить то, что сейчас есть дома, без требования заполнить всю кухню.
4. Голос: запись → расшифровка → выделение продуктов и количеств. Фото чека и ручной ввод попадают в такой же черновик.
5. Один экран уточнений: например, «две пачки творога — сколько граммов в каждой?». Ответить можно текстом, голосом или подходящей кнопкой. Примерная оценка должна быть явно подтверждена.
6. Карточки распознанных продуктов и КБЖУ из каталога. Отсутствующие данные запрашиваются; данные модели не объявляются информацией с этикетки.
7. «Добавить N продуктов» сохраняет весь подтверждённый набор один раз.
8. После подтверждённого сохранения — короткое сообщение «Продукты уже на полке. Теперь подберём, что приготовить.» и возврат на главную с подборками. Отдельного промежуточного экрана выбора рецепта нет. Пока продуктов нет, «Идеи для тебя» не показываются; доступная готовая еда остаётся видимой.

Согласованный сценарий: одна голосовая сессия внутри Mini App. Пользователь диктует продукты и голосом отвечает на текстовые уточнения. Бренд и КБЖУ сначала ищем в каталоге, уточняем лишь необходимые отсутствующие данные. Микрофон выключен либо распознано явное завершение «всё / готово» — показываем итоговый редактируемый список для утверждения. Завершение записи не означает согласие на сохранение. Голосовое «всё / готово» распознаётся как отдельная команда, а не как часть названия продукта или случайная пауза. Озвучивания ответов нет. Потоковая сессия — UX приложения, технически возможна отправка коротких аудиофрагментов с сохранением единого черновика. Отказ в доступе к микрофону оставляет текстовый/ручной ввод. Бот — только вход.

## ИИ: предложение к проверке

- Текст, пожелания, уточнения и адаптация: DeepSeek V4.1 Flash через Timeweb AI Gateway.
- Фото чеков: отдельная модель с подтверждённым приёмом изображений в Timeweb; первоначальный кандидат — Gemini 3.8 Flash. Наличие в каталоге не заменяет проверку конкретного API/model ID на настоящих обезличенных чеках.
- Голос: отдельная STT-модель из аудио API Timeweb → текстовая модель для смысла и уточнений. Сначала короткие записи; реальная потоковая транскрибация через этот сервис не заявлена.
- Не подключать общий чат или общую память агента ко всем пользователям. Хранить явные предпочтения и события у себя, собирать ограниченный контекст по авторизованному ID.
- Сравнить качество на одинаковых запросах/профилях/чеках до фиксации модели. Считать фактические входные, выходные и аудиотокены, повторы, задержки и долю исправлений. Предыдущие оценки прямого API не переносить на тарифы Timeweb.

Источники: [AI Gateway](https://timeweb.cloud/docs/ai-gateway), [каталог](https://timeweb.cloud/services/ai-gateway), [аудио](https://timeweb.cloud/docs/ai-gateway/audio-api), [ограничения вложений агентов](https://timeweb.cloud/docs/ai-agents/manage-agents/attachments-in-chats), [проверка Telegram initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Telegram-вход и PostgreSQL в интерфейсе

Подключён вход по проверенному initData, загрузка своих данных, выход, отдельное демо и подтверждаемый перенос старых локальных записей без удаления исходника. Пользовательское состояние сохраняется в PostgreSQL атомарным версионированным JSONB-агрегатом, с блокировкой строки, конфликтами 409 и идемпотентными повторами. При потерянном ответе запрос сохраняется по UUID аккаунта и повторяется без двойного списания. Добавлена сессия в памяти для фреймов Telegram, где cookies недоступны. Подробности — USER_DATA.md.

P3 остаётся частично выполненным: расчёты и построение действий приготовления/еды пока общие клиентские доменные функции; сервер проверяет состояние и сохраняет его транзакционно. Предметные команды и отдельные таблицы партий/событий можно выделить следующим этапом, не выдавая их за уже реализованные. Облачные ресурсы, реальный Telegram-бот, синхронизация в реальном времени, голос и Timeweb AI этим изменением не подключены.
